# Tag Conversion

Conversion connects inline tags to Joplin's note-level tags. The converter uses
the existing parser to identify inline tags and keeps conversion history in
per-note Joplin user data when `Tag conversion tracking` is enabled.

## Prefix Recognition

`hasInlineTagPrefix` in `src/utils.ts` implements the existing frontmatter rule:
test a candidate with the configured `Tag regex`, resetting its position before
each test. Reverse conversion applies space replacement before detection, so a
Joplin name such as `@alice smith` becomes `@alice_smith`. A recognised tag keeps
its prefix; an unrecognised name receives the configured `Tag prefix`.

Frontmatter parsing uses this detection while retaining its existing lowercase
and whitespace normalisation. Reverse conversion uses `formatInlineTag` for
generated text, duplicate checks and tracked removal. No fixed list of prefixes
or additional settings is needed.

Joplin names that produce the same inline representation (such as `alice` and
`#alice`) share one emitted tag. Tracking retains it while either association exists.

## Reverse Conversion

With tracking off, the converter rebuilds managed tag-list lines from the current
Joplin tags, omitting tags already represented elsewhere in the note. With
tracking on, it adds missing tags and removes previously tracked tags from
managed tag-list lines when their Joplin associations disappear.

Tracking checks for missing inline tags after removal. This preserves a native
parent tag when removing its child also removes the parent's inferred occurrence.
Duplicate checks also account for a `List prefix` without trailing whitespace;
the written prefix retains its configured form.

A managed line begins with `List prefix`, followed by an empty payload, the
configured prefix, or a regex-recognised tag at the start of the payload. A
matching tag later in a YAML value does not make the line a managed list.
Removal matches complete formatted tags, preserving longer names and inline tags
in ordinary body text. New lists are inserted after leading YAML frontmatter.

Existing conversion history remains a list of Joplin tag names. This fix does
not migrate previously generated malformed tags or change synchronisation policy.

## Conversion Controls

`Tag conversion exclusion regex` is compiled case-insensitively and validated
with the shared regex-safety check before either direction starts. Invalid
patterns cancel the operation with a toast, including before bulk processing.
Older clients without the toast API receive the same message in a dialog.
An empty pattern includes all tags. There are no additional tracking fields.

Both parser entry points accept optional occurrence filtering and expansion
controls. Conversion filters before date resolution and nested-tag expansion,
including for generated frontmatter forms. Projected parent/key tags must also
pass the same exclusion rule in their formatted inline form. The expansion
option controls only parent and bare-key generation, respecting global
`nestedTags`; date parsing retains the original syntax settings. Indexing callers
and reverse conversion retain the default expansion behaviour.

Tracking ignores excluded names when computing removals. Names from history are
tested using their generated inline form. Families generated by currently
excluded raw occurrences are also protected during inline → Joplin conversion.
History retains the existing snapshot format; no original-prefix or source
provenance is added. Exclusions do not clean up old converted tags, and turning
expansion off uses existing tracking cleanup rather than introducing mirroring.

Reverse conversion tests each native tag's formatted inline output. Simple-mode
rebuilds retain excluded raw tags in managed lists, then use the existing list
writer for the remaining tags. Tracking mode filters removals by the same rule.
Filtering a tag out is never treated as evidence that it was deleted.

The parser's shared inline matcher scans the full line with the same lowercase
normalisation as indexing. List edits use its source ranges to preserve excluded
tags' spelling and unparsed text, including when Unicode lowercasing changes
length. Reading and editing share the existing boundary handling for a
`List prefix` without trailing whitespace. The list writer also provides the formatter
used by the default no-change check, preserving an already matching list's position.
